# 微观模块：城市内找房与具体房源分析

柏林默认房源扫描、先筛后入库、定期增量更新及 Output 本地数据库流程见 [listing_workflow.md](micro/listing_workflow.md)。

## 输入与检索策略

提取城市、城区或通勤目的地、用途、总预算与首付、融资、持有期，以及户型/卧室数、面积及口径、房龄、楼层/电梯、产权类型、交付状态、装修、停车和交通等条件。把硬性条件与偏好分开；学校或落户需求需查询当前适用政策，不以中介承诺作为保证。

预算分为房价预算与包含税费、交易费用、必要装修的总投入预算。不能据后者直接筛选同金额的挂牌房价。

按当前工具能力搜索公开房源平台、机构/开发商官网及当地可用的成交记录。记录平台、查询日期、区域、筛选条件、检索词和实际覆盖量；要求全量时执行 listing_workflow.md 的分页与覆盖验收，无法完成则明确标注未完成。仅在一个平台检索时明确覆盖限制。用户给出链接或资料时先分析这些目标，不强制扩展搜索。

受登录、验证码或付费限制时，记录缺口，改用可访问来源或用户提供的材料，不把搜索摘要当作完整核验。找不到合格房源时说明原因及可调整条件，不编造候选或暗中放宽硬性条件。

## 房源表与核验

每条候选至少记录：

| 字段组 | 内容 |
| --- | --- |
| 身份 | listing_id、城市/城区、小区或公开地址、原始链接、平台、抓取/访问日期、挂牌或更新时间、当前可见状态 |
| 价格 | 原币种、挂牌总价、单价、价格变更；成交价只在有可验证记录时单列 |
| 房屋 | 物业类型、面积数值和口径、户型、建成年份/房龄、楼层与总层数、电梯、装修、朝向（若可得） |
| 权利及费用 | 产权/租赁权类型、土地或租赁剩余年限、物业/管理费、税费、能源和维修信息（按当地制度） |
| 匹配 | 硬性条件是否满足、偏好匹配、通勤依据、出租现状、主要风险、缺失项、来源 ID |

CSV 字段可按实际任务展开，未知值留空，并在 missing_fields 或 notes 中说明；未知不能填 0 或“无”。精确个人住址等敏感内容仅在用户提供且分析必需时保留，报告避免披露不必要的个人信息。

根据链接 ID、位置、小区、面积、户型、楼层及照片等可得信息去重。同一套房多个渠道合并为一个候选并保留来源和价格差异；疑似重复但无法确认时标记，不强行合并。不同单元不能仅因面积相同被合并。

挂牌可见不等于仍可售，挂牌日期不等于最近核实日期。没有直接验证时写“页面可见，实际可售待确认”。广告中的学区、收益承诺、未来交通、产权和无瑕疵等内容只列为待核实主张。

## 从候选到短名单

先筛硬性条件，再按用户目标比较。对缺失关键硬性信息的房源放入待确认组，不视为已符合或直接判定不合格。候选数量由有效搜索结果决定；用户指定数量却不足时报告实际数量。

短名单说明每套入选原因、主要代价、总投入、证据质量以及下一步核验重点。评分仅用于透明比较，不用小数分数掩盖口径不一致或数据缺失。

通勤按真实起终点、出行方式与时段估计，标记地图或路线来源；直线距离不当作通勤时间。学区、分配或招生资格、规划交付与治安/灾害信息使用适用辖区的可靠来源，并区分现状与规划。

## 估值与议价

优先选择同小区或附近可比物业的近期真实成交，再考虑挂牌可比。记录每个可比的日期、位置、面积口径、楼层、房龄、装修和权利差异。找不到真实成交时只能提供挂牌比较范围，不能称为成交估值。

- 展示样本数量、范围和异常值处理理由；小样本明确降低置信度，不强求固定数量。
- 对面积、楼层、装修、权利与交易日期的调整说明证据。缺少证据时作定性说明或区间敏感性分析，不随意设定“每层溢价百分比”。
- 给出估值区间、主要依据与敏感项；议价区间结合可比价格、已知瑕疵及市场流动性，不把挂牌与估值之差直接视为卖方可接受折扣。
- 购房上限同时受用户总预算、偿债能力与估值约束；缺少融资或收入信息时，不输出已通过负担能力验证的购买建议。

## 成本、贷款与收益

先核实当地税费适用主体、税基、贷款条款和支付时点，再测算。区分一次性购入费用、资本性改造、经常支出及退出费用；税种和费率不能跨国家套用。

基本计算（所有期间和币种必须一致）：

- 总购入成本 = 房价 + 购入税费及交易费用 + 必要初始装修/整备。
- 初始现金投入 = 总购入成本 − 实际放款额；另列购后应急储备及首付款与贷款到账时点的资金缺口。
- 等额本息月供：`M = L × r × (1+r)^n / ((1+r)^n − 1)`，L 为本金，r 为月利率，n 为月数；r = 0 时 M = L/n。名义年利率按合同频率转换；有效年利率转月为 `(1+i)^(1/12)−1`。其他还款方式、固定利率期后的重定价、尾款和贷款费用按合同另算，不能套用单一月供公式。
- 年有效租金 = 月租 × 12 × (1 − 空置率)，加上有依据的其他租赁收入；租金必须是可比房源的可靠租金或明确假设，不能把售房广告的收益承诺当作已实现收入。
- 年净经营收入 NOI = 年有效收入 − 业主承担的经常性经营费用。经营费用可包括管理、保险、日常维护和适用持有税；不含还本付息、资本性支出和个人所得税。
- 净经营收益率 = NOI / 总购入成本；若另用房价作分母，明确命名为基于房价的收益率，不混用。
- 税前持有现金流 = NOI − 年债务偿付 − 当年资本性支出；现金回报率 = 税前持有现金流 / 初始现金投入。额外注资需另记，初始现金为零或负时不报告此比率。
- 税后结果只在掌握适用税制和用户纳税条件时计算，否则标记税前。折旧及税收处理不能直接当作现金流支出。

月供中的本金影响现金流但不是经营费用；退出回款必须扣除剩余本金和出售费用，避免把偿还本金重复计为投资损失或收益。多期 IRR 如适用，列出全部现金流时点、资本支出、退出价格假设；不能用一年租金收益率替代总投资回报。

自住任务加入租房对比：可比住房租金、持有成本、首付资金机会成本、交易摩擦及持有期限。把本金积累与消费成本分开，不把全部月供视作住房成本。

至少对影响结论最大的变量做敏感性分析，如租金、空置、维修、重定价利率、收入或退出价格。压力幅度来源于当地证据或用户设定，并标明假设；无需机械套用所有变量。未知重大维修或特殊收费单独揭示。

## 实地与交易前核验

按当地物业制度及房源情况列出真正相关的核验项：权属与负担、租约/腾退、建筑和使用许可、结构与渗漏、消防/能源、灾害暴露、管理组织财务、重大维修和特殊收费、新房开发与交付风险等。公开信息不能替代现场检查或登记文件，未核实项保持未核实状态。

对每项说明所需材料、可核实对象和对价格/决策的影响。严重产权或安全问题单列为继续交易前的前置条件，不能被综合评分抵消。

## report.md 推荐结构

1. **结论与适用条件**：优先候选、排除原因、仍需确认的信息。
2. **需求与搜索覆盖**：硬性条件、偏好、平台/日期、实际检索限制。
3. **候选比较**：价格、总成本、特点、通勤、风险与匹配；附来源链接。
4. **重点房源分析**：可比证据、估值或挂牌比较区间、议价依据。
5. **资金与情景**：初始现金、月供、经营收益/持有现金流或租买比较、压力情景。
6. **下一步**：看房清单、需索取的材料、会改变结论的条件。
